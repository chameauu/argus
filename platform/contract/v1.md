# Platform contract — v1

**Status:** frozen 2026-11-21. Supersedes nothing.
**Scope:** multi-app, single-operator. One host, one Grafana, one Alertmanager.

A service is *onboardable* when it satisfies all five rules below and nothing else. Onboarding means adding `services/<name>.yaml`. If onboarding a service requires editing `prometheus.yml`, a dashboard JSON, a rule file, or a runbook by hand, the platform has failed its own test.

Every rule is machine-checkable. `platform/contract_check.py <service>` implements the checks; a rule that cannot be checked is not a rule.

---

## 1. Telemetry intake

The service ships OTLP to the collector and identifies itself in resource attributes.

| | |
|---|---|
| **Required** | `OTEL_EXPORTER_OTLP_ENDPOINT=http://otel-collector:4317` (or `:4318` for HTTP) |
| **Required** | `service.name=<name from descriptor>`, `service.namespace=argus`, `deployment.environment=local` |
| **Test** | Tempo search for `resource.service.name="<name>"` returns spans from the last 15 minutes |
| **Failure mode** | Wrong endpoint: spans are dropped silently, requests still succeed, nothing turns red. Wrong `service.name`: traces exist under a name no dashboard queries |

`service.name` must equal the descriptor's `name`. This is the join key between traces, dashboards and rules.

## 2. Metrics endpoint

| | |
|---|---|
| **Required** | `GET /metrics` on the descriptor's port, Prometheus text exposition |
| **Required** | A request counter and a latency histogram, in seconds, labelled `route` (or `endpoint` in v1) and `status` |
| **Platform-applied** | The platform stamps `service="<name>"` at scrape time via `metric_relabel_configs`. The application is **not** required to set it |
| **Required** | The route label is a template: `/work/{id}`, never `/work/1234`, never a user ID |
| **Test** | `/metrics` returns 200; Prometheus stores every series of the job with `service="<name>"`; app series ≤ 500 (enforced); route label has ≤ 50 distinct values, none containing a raw numeric ID or 32-hex identifier |
| **Failure mode** | Broken relabel rule: rules match nothing, `up` is still 1, the alert simply never fires. Raw paths in the route label: one busy endpoint multiplies series until Prometheus OOMs |

Because the platform owns the `service` label, an application that already labels its series remains valid: the relabel config overwrites the label with the same value. Apps do not need to know their platform-side name, and a relabel fix applies to every service at once instead of requiring an app rebuild.

`route` and `endpoint` are both acceptable names in v1. What matters is that the values are route templates and that the distinct-value count stays small. Renaming every service to `route` is deferred to phase 2; the checker treats the two names as equivalent.

Standard runtime families (`go_*`, `python_*`, `process_*`, `promhttp_*`) are exempt from the series budget — they are emitted by a client library, not by the application. Everything else counts.

## 3. Health

| | |
|---|---|
| **Required** | `GET /healthz` returns 200 when the process can accept traffic |
| **Required** | It must not depend on downstream services — a slow database is not an unhealthy process |
| **Test** | 200 within 1 s |
| **Failure mode** | Health that checks dependencies turns one outage into a cascade; health that is absent means `up` is the only signal, and `up` only fires once every 15 s for 3 consecutive failures |

`/health` is not `/healthz`. If a service exposes only `/health`, the contract fails — the platform should not grow two conventions.

## 4. Log correlation

| | |
|---|---|
| **Required** | Every request-scoped log line contains `trace_id=<32 lowercase hex>` on the same line |
| **Required** | Format is pinned: no JSON key, no prefix, no uppercase |
| **Test** | Loki query for the service over 15 minutes returns at least one line matching `trace_id=[0-9a-f]{32}` |
| **Failure mode** | Any other format produces a Grafana derived-field miss, which renders as "no traces" — indistinguishable from a service that never traces. A dead link is worse than no link |

The Grafana derived field is a regex, not a parser. This rule exists because a regex cannot negotiate.

## 5. Descriptor

`services/<name>.yaml`, schema v1:

```yaml
name: target-app
owner: jmal
namespace: argus
environment: local
scrape:   { port: 8000, path: /metrics, interval: 15s }
health:   { path: /healthz }
slos:
  availability: { objective: 0.995, window: 30d, error_selector: 'status=~"5.."' }
  latency:      { objective: 0.95, threshold_seconds: 0.5, histogram: target_app_http_request_duration_seconds }
metrics:
  requests_total: target_app_http_requests_total
  route_label: endpoint
routes_allowlist: [/work, /slow, /error-prone]
runbook: runbooks/target-app.md
```

`metrics` is optional (amendment 2026-11-22). The first two keys name the counter with a
`status` label and the latency histogram in seconds; `route_label` names the label carrying
the route template (`route` or `endpoint`, default `route`).

The latency histogram has **one** home: `slos.latency.histogram`. It feeds the SLO SLI, the
RED latency rule and the dashboard. `metrics` names only the request counter and the route
label. `slos.latency` requires a non-empty `routes_allowlist`: the SLI filters on it, so an
empty allowlist would silently measure scrape and probe traffic too.

The descriptor is the only per-service artefact. Everything derived from it — scrape target, recording rules, burn-rate alerts, RED alerts, dashboard, runbook stub — is generated and never edited by hand.

## Non-goals (permanent, not "later")

Multi-tenancy · RBAC · self-service portal · Kubernetes/operator · HA · long-term storage · per-team routing · Terraform · per-app bespoke exporters · auto-derived or trace-derived SLOs.

Each is a week of work that buys nothing demonstrable on one host, and each invites a question the answer cannot survive.

## Versioning

`contract/v1` is frozen. A breaking change becomes `contract/v2`; both are supported for one release, and the checker reports which version a service satisfies. Adding a rule is breaking. Removing one is not.

## What this buys

Before: onboarding a service is roughly nineteen hand edits across scrape config, rules, dashboards and runbooks, and the result is a one-off nobody can reproduce.

After: one descriptor, and a CI check that fails the app — not the platform — when the contract is violated.

## Amendment log

**2026-11-21 — rule 2 only.** Three changes, all narrowing the rule to its intent rather than loosening it:

- `service` is stamped by the platform at scrape time (`metric_relabel_configs`), not by the application. Services that already set the label stay valid; the relabel overwrites it with the same value.
- The route label may be named `route` or `endpoint` in v1. Renaming to `route` is deferred to phase 2.
- The 500-series budget is now enforced (FAIL), not advisory.

No rule was added or removed. v1 remains backward compatible.

**2026-11-22 — descriptor `metrics` (additive).** The dashboard and RED rules need metric
names, which differ per application and were not expressible in schema v1. `metrics` is an
**optional** top-level block, so every existing descriptor remains valid:

```yaml
metrics:
  requests_total: target_app_http_requests_total          # counter with a status label
  route_label: endpoint                                  # route | endpoint (default route)
```

- `requests_total` is the counter name actually exposed on `/metrics`.
- `route_label` is optional; it names the label carrying the route template. Default `route`.
- The checker validates the block structurally and verifies the declared counter exists in
  the scraped series as extra evidence on the existing `descriptor` check. No ninth check.
- Backward compatible: a descriptor without `metrics` still validates and still generates
  the availability (`Down`) rule, but the RED error-rate and latency rules need declared
  metric names, and no dashboard panels are generated.

No rule was added or removed. v1 remains backward compatible.

**2026-11-22 — one latency histogram (corrective).** `metrics.latency_histogram` was a
second, competing name for the same concept and `slos.latency.histogram` was dead. The
single source is `slos.latency.histogram`; `metrics` keeps only `requests_total` and
`route_label`. The latency SLI filters on `routes_allowlist`, and validation rejects a
descriptor that declares `slos.latency` with an empty allowlist. Existing descriptors that
still carry `metrics.latency_histogram` fail validation and must drop the key.
